## Maintained work register

Follow the table in order for the default working sequence. Work may proceed independently when its prerequisites are met. A preceding row is not automatically a dependency.

Order is display sequence, not an ID or dependency. Phase and checkpoint rows summarize their children; they are not additional implementation actions. The prerequisite column names the actual blocking condition and required stage.

For implementation slices, use these stages as applicable: Awaiting prerequisites → Ready for Opus → Opus planning → Ready for Sonnet → Sonnet implementation → Ready for Luna → Luna review → Sonnet corrections → Luna re-review → Reviewed. Current stages require evidence; no stage is inferred from display order. A checkpoint PR is ready to merge only after all included slices are independently reviewed, PR acceptance cases pass, and CI passes on the integration head. Merge, operational cutover/enabling, browser verification, and owner acceptance remain separate events with separate evidence.

P19-C01 source provenance and P19-C02 rules-neutral calculations are independently eligible alongside P15–P17 under their stated ADR/category gates. Other P19 work follows its own prerequisites; full Phase 19 delivery waits for P17. P19 does not wait for Phase 18. A5c is a separate Luna review-only obligation; it gates the copy-operation consumer and does not block public-tier rendering.

## Execution stages and review gates

**D/** qualifies a proposed delivery ID. **Register** qualifies the current immutable lookup key. **History** identifies the source series (R01, 15H, R19, DEF, CP, DR, etc.). “Previous draft” refers only to the superseded unadopted proposal. Matching numerals across these namespaces do not confer identity. A named evidence record has a stable fragment and a parent. It adds no hierarchy level.

First establish precedence at the stage actually consumed. Then number schedulable checkpoint PRs within their release, slices within each PR and commits within each slice, from 01 in execution order. Children are contiguous. For equally eligible work, the adopted sequence places the active handoff first, then groups independent work by workflow in the published order. That tie-break is scheduling discretion. Only a stated prerequisite creates a dependency. If a condition is resolved later, insert its newly sized PRs before the work or release gate that consumes them and revise the current register and crosswalk before work begins. Historical evidence remains keyed to its original IDs and heads.

**Opus implementation plan → Sonnet implementation → Luna independent review.** In each table the PR row supplies purpose, inherited entry criteria and merge/operational gates. A slice row adds its own entry criteria, task commits and acceptance case. Opus pins a reviewed base and describes the tests, interfaces, intermediate states and named endpoint. Sonnet records the actual SHA of each task and the first test run and reruns. Luna reviews the entire slice from base through the last listed task, including interactions among commits. A correction goes back to Sonnet, then to Luna for re-review through the correcting SHA. Retain both verdicts. Where a slice awaits decomposition, it has a bounded outcome but commit tasks are not invented before the stated inventory or contract is available. Record its reviewed last-task SHA once planned and implemented. No future SHA, test pass or model handoff is claimed here.

Merge requires all included slice reviews, the PR acceptance cases and CI on the integration head. Re-review affected ranges after conflict resolution or material base changes. **Merged**, **cut over/enabled**, **browser verified** and **owner accepted** are distinct events with their own head, actor and evidence. “Verified” on a decision/evidence record means the specific test, rehearsal, acknowledgment or disposition in that row. An owner-approved deferral can satisfy a disposition gate while preserving an unexecuted test or deferred implementation. A phase heading groups outcomes and does not gate every child on the phase exit.
