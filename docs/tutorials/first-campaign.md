# Run your first session

Start with the local API and portal running against a new development database. Use the account created by the administrator bootstrap. It starts with both Admin and Game Master system roles. Set up the instance first if you have not reached the sign-in screen. [Local setup](../operations/start-locally.md)

1. **Create a world.** Sign in and open **Worlds → New world**. Call it *The Saltmarch*, select the offered ruleset and name the primary timeline *Main Timeline*. Save and reopen the world. You should see the timeline and your Owner role in Sharing. The world is the home for shared people, places and definitions.
2. **Create a campaign.** Open **Campaigns → New campaign**. Choose The Saltmarch, Main Timeline and the offered ruleset version. Name the campaign *The Drowned Archive* and submit. Reopen its Home. The creator receives the campaign Owner and GM roles. A different host needs system hosting authority and permission to use this world. Reusing a timeline that already hosts a campaign also requires `timeline.manage`. [Roles and campaign creation](../adr/0020-scoped-system-world-and-campaign-roles.md)
3. **Establish fictional time.** Open **World times** from the campaign. Record a named moment, such as *The harbor bell*. Choose narrative precision if you only know its place in the story. Return to the campaign clock and advance it to that moment. Recording a time makes it available for selection. Advancing the clock changes what the campaign treats as Now.
4. **Bring in another person.** In the campaign access area issue an invitation and privately give the one-time link to the intended player. After acceptance, confirm active membership and assign the required campaign role. Keep the link out of logs and screenshots. To let another GM edit shared world definitions, grant the corresponding world role in the world's Sharing screen.
5. **Run a session.** Open **Sessions**, create a session with a title and optional scheduled start, then open its Run page and start it. Add a public log entry at the recorded time. Use the GM notes field for preparation that other members should not read. Review the log before ending the session. Reopen the completed session to see its recorded outcome.
6. **Check the player experience.** Have the invited player open the campaign in their own session. Compare the public log and the actions available to them with the GM view. A published character field, a released public profile and a knowledge claim revealed to a party have different audiences. [How publication and discovery work](../explanation/worlds-and-play.md)

For a repeatable multi-account rehearsal with expected results, use the [first-campaign acceptance script](../delivery/first-campaign-acceptance.md). Record execution evidence in the [acceptance ledger](../delivery/acceptance-ledger.md).
